## Reglas de colaboración
- Cada entrega tiene un dueño (owner) y un revisor (reviewer) distinto.
- Nadie integra sus propios cambios sin 1 revisión del otro.
- Definición de hecho: código + tests pasan + doc mínima actualizada.

## División de responsabilidades

ROL1 (owner de Módulo A)
- Diseño y especificación breve (objetivos, supuestos, entradas/salidas).
- Implementación de Módulo A.
- Pruebas de Módulo B (caja negra + bordes).
- Revisión de Módulo B (comentarios y aprobación/rechazo).

ROL2 (owner de Módulo B)
- Implementación de Módulo B.
- Pruebas de Módulo A (caja negra + bordes).
- Revisión de Módulo A (comentarios y aprobación/rechazo).
- Redacción del README/Informe final (metodología, resultados, limitaciones).

Sugerencia de módulos si no están definidos aún
- Módulo A: Entrada/Salida + orquestación (parsing, CLI, validaciones básicas).
- Módulo B: Lógica/algoritmo principal + validaciones avanzadas/métricas.

## Cronograma sugerido (5 hitos)
1) Especificación (ROL1 redacta, ROL2 revisa).
2) Implementación Módulo A (ROL1) + tests iniciales para B (ROL2).
3) Implementación Módulo B (ROL2) + perfilado/revisión (ROL1).
4) Pruebas completas y casos borde (ROL2), fixes y pulido (ROL1).
5) Informe/README (ROL2) + QA/entrega final (ROL1).

## Checklist de entrega
- [ ] Especificación breve aprobada por ambos.
- [ ] Módulo A implementado y probado por ROL2.
- [ ] Módulo B implementado y probado por ROL1.
- [ ] Todos los tests en verde.
- [ ] README/Informe actualizado.
- [ ] Archivos listos según rúbrica del curso.
